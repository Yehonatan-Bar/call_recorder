# קול — מקליט אישי לפיקסל

גרסה 1.2. מיועדת לבדיקה על Pixel 8 Pro עם Android 17 (SDK 37).

בבדיקה ידנית של גרסה זו דווח ששני צדדי שיחה סלולרית נשמעו בהקלטה. האימות מוגבל לתצורת הבדיקה ואינו מבטיח תאימות לכל מכשיר או גרסת מערכת; פרטי הבדיקות נמצאים ב־`TEST-RESULTS.md`.

האפליקציה שומרת WAV פרטי במכשיר ומאפשרת התחלה ועצירה ידניות, האזנה, שינוי שם, ייצוא ושיתוף. אין הרשאת אינטרנט, חשבון או גיבוי בענן. הסרת האפליקציה מוחקת את ההקלטות; יש לייצא הקלטות שרוצים לשמור.

## הפעלה לאחר אתחול הטלפון

נדרשים ADB וחיבור USB או Wireless Debugging שכבר צומד. כתובת החיבור עשויה להשתנות. `adb devices -l` מציג מכשירים מחוברים ו־`adb mdns services` יכול לאתר את שירות הפיקסל. יש לבחור את Pixel 8 Pro (`husky`) ולא מכשיר אחר.

```powershell
# Replace these placeholders with the connection address shown on your device.
$DeviceAddress = 'DEVICE_IP:ADB_PORT'
adb connect $DeviceAddress
.\Start-CallBridge.ps1 -Device $DeviceAddress
```

יש להחליף את `DEVICE_IP:ADB_PORT` בכתובת החיבור המוצגת במכשיר. בחיבור USB יש להעביר ל־`-Device` את המזהה שמציג `adb devices`. להתקנה או לעדכון של ה־APK החתום המקומי:

```powershell
.\Start-CallBridge.ps1 -Device $DeviceAddress -Install
```

`-Restart` מפעיל מחדש את רכיב העזר בלבד. הסקריפט מסרב להתקין או להפעיל מחדש בזמן ששירות הקלטה פעיל. הפעלה חוזרת רגילה שומרת על רכיב העזר הקיים. `-Probe` עם הפעלה חדשה בודק אתחול מקורות שמע בלי להתחיל הקלטה.

רכיב העזר פועל בטלפון כמשתמש ADB shell, ללא root. אחרי ההפעלה אין צורך בחיבור למחשב כל עוד התהליך ממשיך לפעול. אחרי אתחול, עצירת ADB בטלפון או סיום התהליך יש להפעילו שוב. לא נפתח bootloader ולא שונתה מדיניות SELinux.

כיבוי המחשב אינו דורש הפעלה מחדש של הרכיב בטלפון. חיבור הרכיב לאפליקציה הוא מקומי בתוך הטלפון ואינו תלוי ברשת; בבדיקה ידנית דווח על פעולה גם לאחר יציאה מרשת ה־Wi-Fi ששימשה להפעלה.

## הקלטת שיחת ניסיון

1. פותחים את **קול** וממתינים לחיווי הירוק **רכיב העזר מחובר**.
2. מתחילים או מקבלים שיחה סלולרית בעצמכם, עם משתתף שיודע שמתבצעת בדיקת הקלטה.
3. חוזרים לקול, בוחרים **ערוץ שיחה**, ולוחצים **התחלת הקלטה**. מאשרים הרשאות אם מתבקשים.
4. מומלץ לבדוק תחילה ללא רמקול: כל צד אומר משפט שונה בתורו, עם כמה שניות שקט ביניהם, במשך 20–30 שניות.
5. לוחצים **עצירה ושמירה** באפליקציה או בהתראה. לאחר השיחה מאזינים ומוודאים ששני המשפטים נשמעים, ושמשך השקט נשמר.

מד עוצמה, קובץ WAV או חיווי ירוק אינם הוכחה לשני צדדי השיחה. קובץ שקט מסומן לבדיקה. אם רכיב העזר חסר או מתנתק, האפליקציה מדווחת על הכשל ואינה עוברת למיקרופון. מצבי **מיקרופון** ו־**זיהוי דיבור** הם מקורות נפרדים ואינם מבטיחים הקלטת שיחה.

## בנייה ובדיקות למפתחים

דרישות: Windows, Python 3, JDK של Android Studio, Android SDK Platform 36, Build Tools 36.0.0 ו־ADB ב־PATH. אפשר לבחור SDK ו־JDK עבור `build.py` באמצעות `--sdk` ו־`--java` או משתני הסביבה `ANDROID_HOME` ו־`JAVA_HOME`. סקריפט בניית הבדיקות מאתר את ה־SDK לפי מיקום ADB.

```powershell
python build.py
python build_device_test.py
adb -s DEVICE install -r build\device-test\test.apk
adb -s DEVICE shell am instrument -w il.co.kolrecorder.test/il.co.kolrecorder.BridgeDeviceTest
```

ה־build מבצע קומפילציה עם SDK 36 ו־JDK של Android Studio, יוצר APK ב־`dist`, מאמת חתימה/יישור, ומריץ בדיקות WAV. בבנייה הראשונה נוצר מפתח פיתוח מקומי ב־`signing`, עם סיסמת הפיתוח הציבורית `android`. המפתח עצמו אינו כלול בריפו. יש לשמרו באופן פרטי לצורך עדכונים שמחזיקים את הנתונים הקיימים; בנייה עם מפתח אחר אינה יכולה לעדכן התקנה קיימת. אין להסיר את האפליקציה הראשית כדי להתקין עדכון.

הריפו כולל קוד מקור, בדיקות ותיעוד. הקלטות, מפתחות חתימה, לוגים, צילומי מסך, נתוני מכשיר ותוצרי בנייה מקומיים אינם מיועדים לפרסום; כללי החרגה נמצאים ב־`.gitignore`. לפני צירוף קבצים לדיווח תקלה יש להסיר מהם פרטים אישיים ומזהי מכשיר.

בדיקת BridgeDeviceTest אינה מחייגת ומסרבת לפעול כשמצב השמע מצביע על שיחה קיימת. היא בודקת חיבור, PING במקביל להקלטה, משך שמע בזמן שקט, סגירה ופתיחה מחדש, התראה, עצירה ושמירת WAV. `-e mode missing` בודק כשל כשהשרת כבוי. `-e mode disconnect` מיועד לבדיקת הפסקת השרת מהמחשב לאחר READY_FOR_HELPER_DISCONNECT. אלה אינן בדיקות של שני קולות בשיחה סלולרית.

אפשר להסיר רק את חבילת הבדיקה לאחר שימוש: `adb -s DEVICE uninstall il.co.kolrecorder.test`.

## מימוש ומקורות

האפליקציה מקבלת Binder רק מתהליך shell (UID 2000), דרך ContentProvider מוגן DUMP ובדיקת UID מפורשת. השרת מאמת את UID האפליקציה ומעביר socketpair דרך Binder. אין חיבור רשת; התעבורה נשארת במכשיר. זה עוקף את הצורך בחיבור Unix socket ישיר, שנחסם במדיניות המכשיר, בלי לשנות אותה.

השמע מגיע רק מ־VOICE_CALL במצב שיחה, בפורמט PCM16 mono, 16kHz. פערים ללא נתונים מתמלאים באפסים לפי שעון מונוטוני. WAV צורך כ־1.9MB לדקה; ההקלטה מוגבלת לשש שעות ונעצרת כשאוזל המקום.

חלקי הקשר ה־shell והגישה ל־ContentProvider הותאמו מ־[scrcpy](https://github.com/Genymobile/scrcpy), תחת Apache-2.0. ראו `NOTICE.txt` ו־`licenses/Apache-2.0.txt`. תיעוד משלים: [שיתוף קלט שמע ב־Android](https://developer.android.com/media/platform/sharing-audio-input), [VOICE_CALL](https://developer.android.com/reference/android/media/MediaRecorder.AudioSource#VOICE_CALL).
